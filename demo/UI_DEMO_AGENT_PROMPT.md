# UI Demo 创建提示词

把下面整段提示词复制给其他 agent，用于在本项目中创建一个最小化、可交互、全假数据的 UI 设计 demo。

```text
你现在在 BossZhiPin_Job_Search 项目中工作。请只在 `demo/ui-dashboard-prototype/` 目录内创建一个独立的前端 UI demo，不要修改真实业务目录，尤其不要改 `tauri-ui/`、`src/`、`src-tauri/`。不要运行 build、type-check、完整测试套件，也不要启动本地服务。完成后只说明文件结构和打开/运行方式。

目标：
创建一个可直接评审的 Boss 直聘自动打招呼桌面 App UI demo。它只使用假数据，不连接后端、不调用 Tauri IPC、不访问网络、不读取真实日志、不发送任何消息。这个 demo 用于确认 UI 设计风格、业务模块、交互方式和用户任务路径；确认后再复刻到真实 `tauri-ui` 项目中。

技术方式：
优先使用最小化 React + TypeScript + Vite 结构，因为真实项目的 `tauri-ui` 也是 React/Vite，后续更容易迁移。不要引入复杂组件库。样式可以用普通 CSS 或 CSS variables，不依赖 Tailwind 也可以。所有数据写在本地 mock 文件或组件常量里。

如果你判断创建 Vite 项目过重，也可以使用单个 `index.html` + `styles.css` + `app.js` 实现，但仍要保持组件化结构和清晰命名。无论采用哪种方式，demo 必须能在浏览器中直观看到交互效果。

产品定位：
这是一个「可审计、可暂停、可 Dry Run 的 Boss 直聘自动打招呼控制台」，不是通用 SaaS 看板。界面核心要让用户放心：
1. 启动前知道是否准备就绪。
2. 运行中知道自动化正在做什么。
3. 出错时知道问题在哪、怎么复制日志求助。
4. 发送前能看见 Dry Run / 真实发送的风险边界。

设计风格：
采用「深色自动化驾驶舱」方向。整体冷静、专业、可信、克制，类似本地桌面工具和自动化控制台，而不是营销页。

视觉约束：
- 主背景使用接近黑色的深灰，不要纯黑。
- 卡片使用轻微层级和细边框，不要过度发光。
- 主行动色使用青色，只用于主要按钮、进度、当前运行状态。
- 绿色只表示安全通过或运行正常。
- 黄色表示 Dry Run、等待确认、轻警告。
- 红色只表示真实危险、失败、停止任务、发送拦截。
- 不要使用紫色渐变、装饰性大光斑、营销式 hero、无意义插画。
- 布局要偏工具型：信息密度适中、可扫描、按钮位置稳定。
- 文案使用中文，保持真实产品语气，不要写教程式大段说明。

核心页面 / 模块：

1. 运行页（首页）
这是 demo 的第一屏，也是最重要页面。

必须包含：
- 顶部状态栏：页面标题、最近同步时间、引擎状态、通知按钮、刷新按钮。
- 运行前检查区：
  - 简历：已上传 / 未上传，显示文件名和更新时间。
  - AI 端点：已配置 / 缺 API Key / 缺模型。
  - Chrome 登录态：已连接 / 需要扫码。
  - 安全模式：Dry Run / 真实发送。
- 主操作区：
  - 未运行时显示「开始 Dry Run」主按钮。
  - 当安全模式切到真实发送时，主按钮文案变为「开始真实发送」，并出现红色风险提示。
  - 运行中显示「暂停队列」「查看实时日志」「终止任务」。
- 本次运行指标：
  - 已扫描岗位
  - 已生成招呼语
  - 已通过审核
  - 已发送
  - 被拦截
  - 失败 / 重试
- 当前阶段进度：
  - 打开 BOSS
  - 检查登录态
  - 读取岗位列表
  - 抓取 JD
  - 生成招呼语
  - 校验内容
  - 发送 / 跳过
  - 写入日志
- 最近活动流：
  - 已读取岗位
  - 生成招呼语通过校验
  - 跳过岗位
  - 拦截异常招呼语
  - 写入审计日志

运行页交互：
- 点击「开始 Dry Run」后，页面进入运行中状态，进度条前进，活动流追加 2-3 条假数据。
- 点击「暂停队列」后，状态变为已暂停，按钮变为「继续运行」。
- 点击「继续运行」后恢复运行状态。
- 点击「终止任务」弹出确认对话框，确认后状态变为已停止。
- 切换 Dry Run 开关时，主按钮和风险提示同步变化。
- 点击「查看实时日志」打开右侧抽屉或下方面板，显示假日志。

2. 简历页
用于确认简历解析和 RAG 状态，不需要真实解析。

必须包含：
- 当前简历卡片：文件名、大小、更新时间、解析状态、向量库状态。
- 假上传区域：拖拽/选择 PDF 的视觉状态即可，不需要真实读取文件。
- 简历召回预览：展示 3-4 条假切片，例如「项目经历」「技术栈」「业务成果」。
- 重新解析按钮、替换简历按钮。

简历页交互：
- 点击替换简历，模拟选择成功并更新文件名。
- 点击重新解析，状态短暂变为解析中，然后回到已完成。

3. 记录页
对应真实项目里的 `letters.jsonl` 和 LLM telemetry。

必须包含：
- 顶部汇总：总调用次数、估算成本、已发送、被拦截。
- 筛选器：全部 / 已发送 / Dry Run / 被拦截 / 失败。
- 历史表格字段：
  - 时间
  - 岗位 / 公司
  - 模型
  - 校验结果
  - 发送状态
  - 招呼语摘要
- 点击行展开详情，显示 JD 摘要、生成招呼语、校验原因、日志片段。

记录页交互：
- 筛选器能切换表格内容。
- 点击表格行能展开 / 收起详情。
- 有一个「复制此条日志」按钮，点击后显示已复制反馈即可。

4. 配置页
对应真实项目里的 `.env` 配置。

必须包含：
- 界面语言：中文 / English 下拉，但 demo 可以只展示中文。
- AI 端点：
  - 常用快捷
  - LLM_BASE_URL
  - LLM_MODEL
  - LLM_API_KEY（脱敏）
- 运行参数：
  - BOSS_USR_NAME
  - BOSS_LABEL
  - BOSS_MIN_MATCH_SCORE
  - BOSS_EXCLUDE_KEYWORDS
  - DRY_RUN
- 自定义招呼语 prompt 文本框。
- 保存按钮、未保存提示、保存成功提示。

配置页交互：
- 修改任意字段后显示「有未保存更改」。
- 点击保存后显示「已保存」，但只更新前端状态，不写文件。
- API Key 可以显示 / 隐藏。

5. 帮助 / 诊断页
用于降低普通用户排障成本。

必须包含：
- 一键复制「问 AI」按钮。
- 环境体检摘要：Chrome、简历、LLM、日志目录、当前版本。
- 常见问题卡片：
  - 需要扫码登录
  - API Key 缺失
  - 简历未上传
  - Chrome profile 被锁
  - BOSS 页面加载失败

帮助页交互：
- 点击复制问 AI，显示复制成功反馈。
- FAQ 卡片可展开 / 收起。

整体导航：
左侧固定导航，建议栏目：
- 运行
- 简历
- 记录
- 配置
- 帮助

底部显示当前账号假数据：
- 用户名：陈思远
- 状态：Boss 直聘 · 已连接

推荐信息架构：
- 左侧栏宽度 240-280px。
- 顶部栏高度 64-72px。
- 主内容区最大宽度可以撑满桌面，不要做窄网页居中布局。
- 首页采用 12 栅格或 CSS grid：
  - 运行前检查横跨整行。
  - 指标卡片一行 4-6 个。
  - 当前阶段进度占左侧 2/3。
  - 最近活动占右侧 1/3。

假数据要求：
请使用与项目真实业务贴近的中文假数据，不要使用 lorem ipsum。

示例数据：
- 今日已扫描：68
- 已生成招呼语：46
- 已通过审核：43
- 已发送：32
- 被拦截：3
- 失败 / 重试：2
- 当前岗位：前端开发工程师 · 上海 · 星河互动
- 模型：deepseek-chat
- Provider：DeepSeek
- 简历：陈思远_前端开发_2026.pdf
- BOSS_LABEL：前端开发（上海）

关键用户任务路径：
1. 用户打开 App，看见运行前检查全部通过。
2. 用户确认 Dry Run 开启，点击「开始 Dry Run」。
3. 用户观察阶段进度和最近活动，打开实时日志。
4. 用户进入记录页，展开一条招呼语，确认生成质量。
5. 用户回到运行页，切换到真实发送模式。
6. 系统出现明确风险提示，用户确认后开始真实发送。
7. 运行过程中用户可以暂停、继续或终止。
8. 出错时用户进入帮助页，复制诊断信息问 AI。

- 不要运行构建、类型检查或启动服务。

迁移提示：
实现时尽量把页面拆成能迁移到真实 `tauri-ui/src/pages` 的结构，例如：
```
